# M30 — 헤더를 비우고, 아이템 탭을 다루기 쉽게, 설명을 한글로

사용자 지시 아홉 가지(M29 배포 뒤 화면을 보고):

| # | 지시 | 한 것 |
|---|---|---|
| 1 | 패널 버튼에 「덱」·「전체 루트」 글자와 제공한 세 줄 아이콘 | `PanelToggle` — `Menu` 아이콘 + 글자 |
| 2 | 제목 「거울 던전 루트」 삭제 | 지웠다 |
| 3 | 우측 나머지 아이콘의 자리 | 「⋯」 팝오버(사용자가 고름) |
| 4 | 검색 결과가 검색창 바로 아래 | 질의가 있는 동안 격자를 위로 |
| 5 | 선택한 아이템 정렬(기본 선택 순서·키워드·이름) | 트레이의 정렬 드롭다운 + `wanted`를 고른 순서로 |
| 6 | 노선도의 「관측」 글자 삭제, 분리만 유지 | 글자는 `aria-label`로만 |
| 7 | 강조색을 흰색(다크)/검정(라이트) | accent에서 색조를 뺐다 |

| 9 | 선택한 아이템 필터(키워드·팩) | 트레이의 필터 칩 둘 |

## 1. 헤더 (1·2·3)

제목은 패널 버튼이 대신한다 — 버튼이 「덱」·「전체 루트」라고 말하면 화면이 무엇인지 따로 적을 이유가
없다. 아이콘은 양쪽 다 세 줄 표시이고, 글자가 곧 버튼의 접근 이름이라 `aria-label`이 경쟁하지 않는다
(그래서 테스트도 `name: '덱'`으로 연다).

넷을 어디로 옮길지는 사용자가 골랐다 — **「⋯」 팝오버**. 한 번에 하나씩 쓰는 것들이라 문 옆에서 눈을
끌 이유가 없고, 푸터와 달리 스크롤 없이 닿는다. 팝오버는 `DetailSurface mode="popover"`라 오버레이
스택·Escape·바깥 누름이 이미 있는 규칙 그대로 붙는다.

## 2. 강조색 (7)

보라(`#5647c9` / `#a89ff5`)를 버리고 라이트 검정·다크 흰색으로. 실측 19.44:1 / 18.71:1이다. 색조를
버렸으므로 팔레트의 색조는 키워드 배지와 판정 링 둘뿐이 됐고, accent는 여전히 무대에 선 층 칸 한
곳에만 쓴다.

## 3. 아이템 탭 (4·5·9)

- **검색 결과가 검색창 바로 아래**로 온다. 그 사이에 필터·관측 슬롯·선택 트레이가 있어서, 검색해
  놓고도 결과를 보려면 한 화면을 내려야 했다. 질의를 지우면 격자는 원래 자리(탭 맨 아래)로 돌아간다.
- **정렬**(선택 순서·키워드·이름)과 **필터**(키워드·팩)를 선택 칩 줄 위에 한 줄로 뒀다. 둘 다
  `wanted`를 **보는 방식**일 뿐이라 칩이 숨어도 선택은 그대로다(숨은 칩도 목표로 남는다). 필터
  후보는 선택한 것이 실제로 가진 키워드와, 선택한 것이 전용으로 매인 팩뿐이다 — 아무것도 걸리지 않는
  선택지를 내지 않기 위해서다.
- 그래서 **`wanted`를 고른 순서로** 바꿨다(`toggleWanted`의 id 정렬 제거). 「선택 순서」가 뜻을
  가지려면 저장된 순서가 고른 순서여야 한다. 플래너는 `expandRequirements`가 goal을 스스로 정렬하므로
  루트는 순서에 영향받지 않는다(테스트로 확인).

## 4. 설명의 한글 (8)

원본 텍스트는 버프를 **대괄호 id**로 적고(「[Combustion] 횟수를 부여」) 게임이 실행 중에 이름을
덧칠한다. 우리 복사본은 id를 그대로 들고 있어서, 한국어로 읽어도 설명이 반쯤 영어였다.

`BattleKeywords.json`이 게임 자신의 id→이름 표다(언어별, 571개). `scripts/lib/battle-keywords.ts`의
`localizeBuffTokens`가 빌드 끝에서 기프트 설명과 조건 문장의 토큰을 양쪽 언어로 고쳐 쓴다 — 한국어는
「[화상]」, 영어도 게임의 제 이름(「[Burn]」)으로 바뀐다. 전체 1622건 중 **1443건**이 바뀌고, 표에
없는 **37개 id**(인격 전용 버프 `BloodDinner` 같은 것)는 **그대로 둔다** — 추측한 이름보다 보이는
id가 낫고, 빌드가 몇 개 남았는지 알린다.

숫자가 아니라 글자로 시작하는 토큰만 바꾼다: 「(최대 [3])」은 글이 뜻하는 숫자이지 못 찾은 버프가
아니다.

## 5. 검증

`npm run check` 통과(**398 tests**, 새 회귀 6개) · `npm run build` 성공 · `public/data`는 이 빌드의
결과를 같은 커밋에 넣었다(gifts.json 738줄).

브라우저(`vite preview` + playwright-core): 1440×900·400px × 라이트/다크 네 조합에서 콘솔 에러 0.
헤더가 「덱 / ⋯ / 전체 루트」뿐인 것, 검색 중 격자가 검색창 바로 아래(격자 상단 192px, 검색창 하단
136px)인 것, 트레이에 정렬·키워드·팩 셋이 서는 것, 층 칸 테두리가 검정(라이트)·흰색(다크)인 것,
그리고 진혼 상세 시트에 「[화상]」만 있고 라틴 토큰이 하나도 없는 것을 확인했다.

## 6. 남은 것

- 표에 없는 37개 버프 id. 게임의 다른 로컬라이즈 파일에 이름이 있다면 같은 자리에 표를 더 붙이면
  된다(`readBattleKeywordNames`에 파일을 추가).
- 인격 스킬 텍스트에도 같은 토큰이 있다. 지금은 화면에 그대로 나오지 않아 손대지 않았다.
