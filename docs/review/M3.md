# M3 — 웹 UI

커밋: `M3: 웹 UI`

## 무엇을 했나

한국어 우선 단일 페이지 앱입니다. 백엔드 없이 `public/data`를 fetch해 브라우저에서 계산합니다.

## 읽는 순서

1. `src/app/App.tsx` — 화면 구성과 데이터 로딩
2. `src/app/store.ts` — 상태와 URL 공유
3. `src/app/DeckPanel.tsx` — 덱 편성
4. `src/app/GiftPanel.tsx` — 기프트 선택
5. `src/app/RoutePanel.tsx` — 옵션과 루트 표시
6. `src/app/condition-text.ts` — 조건 문구 한국어화
7. `src/app/i18n.ts` — 모든 UI 문자열
8. `src/app/__tests__/app.test.tsx`

## 설계 판단

**조건 문구는 UI가 만든다.** 코어는 `ConditionReport.subject`에 내부 id(`THUMB_FINGER`)만 담고, UI가 `enums.json`으로 `엄지`로 옮깁니다. 코어에 표시명이 들어가면 언어 전환이 불가능해집니다.

**공유 링크가 localStorage보다 우선.** 링크를 받은 사람이 자기 예전 상태를 보면 링크가 무의미하므로, 해시가 있으면 해시를 적용합니다.

**모바일은 탭, 데스크톱은 3열.** 같은 컴포넌트를 `hidden lg:block`으로 전환합니다.

## 봐 주셨으면 하는 점

1. **한국어 문구가 자연스러운지.** `src/app/i18n.ts` 한 파일에 모여 있습니다. 어색한 표현은 그 파일만 고치면 됩니다.
2. **루트 화면이 실제로 따라 하기 쉬운지.** 층 → 팩 → 챙길 기프트 순서가 플레이 흐름과 맞는지.
3. **범용 드랍 안내가 충분히 분명한지.** "확정이 아니다"가 오해 없이 읽히는지가 이 도구의 신뢰도를 좌우합니다.
4. 모바일에서 기프트 목록(최대 200개 표시)이 쓸 만한지.

## 알려진 한계

- 기프트 목록은 상위 200개만 렌더링합니다(가상화 대신). 필터로 좁히면 문제없지만 전체 훑기에는 불편할 수 있습니다.
- 인격·기프트 아이콘이 없습니다(에셋 재배포를 피했습니다).
- 덱 슬롯에서 출격 6인을 직접 고르는 UI가 없습니다. 편성 순서 앞 6명이 자동으로 출격입니다.
- 조건이 여러 개인 기프트는 조건마다 한 줄씩 나옵니다.
