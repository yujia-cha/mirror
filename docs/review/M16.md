# M16 — 특수 충전 표기 · 키워드 개수 숨김 · 팩 한정 아이템 우선

커밋: `M16: 특수 변형(특수 충전 등) 도출·표기 · 인격 칩 개수 삭제 · 팩 한정 기프트 우선 정렬`

## 무엇을 했나

사용자 지시 3가지.

1. **특수 충전 표기** — 게임은 「특수 충전」(생체 재료 `ChargeBodyArt`)을 별도 버프로 두고, 사원증(9043) 같은 기프트는 「[Charge] 횟수 **또는 특수 충전**」이라고 명시한다. 파이프라인은 지금까지 `buffKeyword`가 7키워드와 정확히 일치하는 것만 셌고 `special`은 항상 `false`였다(curated 보정 파일은 비어 있었다).
   - `readSpecialVariants()`(`scripts/lib/raw.ts`)가 `BattleKeywords.json` 설명에서 「- 특수 충전」처럼 **한 줄로 선 특수 X** 를 찾아 버프 id → 키워드 표를 만든다. 하드코딩 없이 6개가 잡힌다: 생체 재료→충전, 못·홍매화·바늘→출혈, 흑염→화상, 셰우트의 균열→침잠.
   - `deriveIdentityKeywords()`가 공격 스킬의 `buffKeyword` **또는 스크립트명**(`MarkGiveChargeBodyArtTurn`)에서 변형을 찾아 `specialSkills`로 따로 센다. 스키마는 `{ skills, specialSkills }`(둘 중 하나는 > 0)로 바뀌었고 `special: boolean`은 사라졌다.
   - 결과: 10명이 특수 변형을 부여한다. 거미집 약지 제자(10215)·약지 아비(10614) = 충전 + 특수 충전. N사 큰 망치(10504)는 키워드가 없던 인격에서 **특수 출혈만** 부여하는 인격이 됐고, 검계 살수(10208)·N사 중간 망치(10304)에 특수 출혈이 추가됐다. 기존 `skills` 값은 한 명도 바뀌지 않았다.
   - core: `DeckStats.baseKeywordCounts`를 추가하고, `keywordSkillCount` 조건은 `includesSpecial`(파서가 채우기만 하고 아무도 읽지 않던 필드)에 따라 특수 포함/기본만을 고른다. 데이터상 출혈·충전·화상·침잠 조건은 전부 「또는 특수 X」형이라 실제 판정은 그대로이고, 특수 전용 인격이 기본만 세는 조건(파열·호흡·진동 일부)을 올리지 않게 막아 둔 것이다.
   - UI: 인격 칩은 「충전(특수)」(기본 + 특수), 「특수 출혈」(특수만)로 적는다. 툴팁이 조건 판정 규칙을 한 줄로 알려 주고, 검색에서 「특수 충전」이 걸린다.
2. **키워드 개수 숨김** — 인격 칩에서 「침잠 **5**」의 숫자를 지웠다. 이름만 남는다(잔향・외로움 료슈 = 「침잠」「진동」). 덱 요약 칩의 「출혈 3/4」는 인격 수라 그대로다.
3. **팩 한정 아이템 우선** — 아이템 격자의 각 섹션(활성/거의 활성/기타) 안에서 `packLimited`·`clearReward`(`isPackBound`)가 맨 앞에 오고, 그다음 조건 진행률, id다. 루트를 실제로 결정하는 것은 팩 한정 기프트이므로 먼저 보이게 했다.

## 핵심 규칙

- **특수 변형은 기본 키워드가 아니다.** 조건 문장에 「또는 특수 X」가 있을 때만 센다(`includesSpecial`). 인격 데이터는 둘을 `skills`/`specialSkills`로 나눠 두고, 덱 통계도 `keywordCounts`(둘 다)/`baseKeywordCounts`(기본만)로 나눈다.
- **변형 목록은 게임 텍스트에서 읽는다.** `BattleKeywords.json`에 「특수 X」 한 줄이 선 버프만 변형이다. 문장 속에서 특수 X를 언급만 하는 버프(초아광축전 등)는 변형이 아니다. 하나도 못 읽으면 `data:validate`가 strict 경고를 낸다.
- **인격 칩에는 숫자가 없다.** 이름(+특수 표시)만.

## 남은 것

- 특수 변형이 있는 다른 키워드 조건(파열·호흡·진동)은 데이터에 특수 전용 인격이 없어 `baseKeywordCounts` 경로가 실데이터로는 검증되지 않는다(합성 조건 테스트로만 확인).
- 특수 변형 여부를 `enums.json`에도 실어 UI가 「특수 X」 설명을 데이터에서 읽게 할 여지가 있다. 지금은 i18n 문자열이다.
