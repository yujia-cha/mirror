# M17 — 관측 지정 존중 · 시작 기프트 우선순위 · 1층 복귀 시 시작 기프트 기록 취소

커밋: `M17: 관측 지정 존중(범용·시작 풀)·시작 기프트 우선순위 · 1층 복귀 시 시작 기프트 기록 취소 · 관측 엣지 테스트`

## 무엇을 했나

제보: 프레스티지 카드(9191)·생강꽃 가지(9419)·깨진 안경(9423)을 관측 지정(3/3)하고 서릿발 발자국(9410, 조합 전용: 귀신 들린 신발 9408 ← 공장 자동화 1004 1~2층, 얼어붙은 아우성 9409 ← 사랑할 수 없는 1005 1~2층)을 목표에 넣었는데 「필요 팩 0 · 확보 4/4」, 1층 「계획된 팩 없음」, 시작 행에 관측 타일 없음. 원인은 두 겹이었고 둘 다 CLI·시뮬레이션으로 재현했다.

1. **core — 범용 기프트에 건 관측 지정이 조용히 버려졌다.** 2단계가 9191을 `generalDrop`으로 분류한 뒤, 지정 관측은 `via === 'route'`인 요구만 봤다. 경고도 슬롯 소비도 없어 유연성 단계가 그 슬롯으로 9409를 관측해 1005를 풀었다(관측 [9419 지정, 9423 지정, 9409 **추천**], 필요 팩 1). 시작 기프트로 잡힌 기프트·보유·미해결 기프트의 지정도 같은 경로로 사라졌고, 시작 풀 30종이 전부 범용이라 **시작 기프트는 한 번도 골라지지 않고 있었다**.
   - 순서를 「라우팅 불필요 분류 → Hard 전용 → **지정 관측** → 시작 기프트 → 탐색·구제·유연성」으로 바꿨다. 지정은 이 단계의 유일한 사용자 결정이라 맨 앞이다.
   - 지정은 `route`·`generalDrop` 요구에 적용되고, 관측한 범용 기프트는 `generalDrops`·「확정 아님」 경고에서 빠진다(`generalDrops`는 관측·시작 기프트 결정 뒤에 다시 계산).
   - `chooseStart`도 `generalDrop` 요구를 받아 원하는 범용 기프트가 시작 풀에 있으면 공짜로 확정한다(`--want 9047,9093` → 시작 기프트 가시 올가미).
   - 보유(`owned`)·미해결 기프트의 지정은 조용히 건너뛰고(앱은 1층 이후 지정 기프트가 항상 보유 상태가 된다; 미해결은 이미 이유가 있다), **계획에 없는 기프트**의 지정만 `observation-trimmed`에 합쳐 알린다. `normaliseOptions`는 경고를 직접 내지 않고 잘라낸 id를 돌려준다.
   - `start.observed`는 지정을 **지정한 순서**로, 추천은 id 순으로 둔다.
2. **app — 1층을 떠날 때 'got'으로 기록한 시작 기프트가 되돌아와도 남았다.** `enter`/`next`는 1층에서 `plan.start.observed`(지정+추천)+시작 기프트를 'got'으로 만드는데 `leave`는 그 팩 전용 기프트만, 스트립의 건너뜀 취소는 아무것도 초기화하지 않았다. 입장→돌아가기를 반복할 때마다 추천 관측이 「보유」로 굳고 빈 슬롯으로 다음 재료를 또 추천했다: 0회 관측 [9419*,9423*,9409] 팩 1 → 1회 [9408] 팩 0 → 2회 [] 팩 0 · 확보 4/4 — 제보 화면 그대로.
   - `RunState.startGifts`(기기 저장, 공유 링크 제외)에 1층을 처음 떠날 때 기록한 id를 남기고, `moveFrontier`가 프런티어 이동 네 곳(`visitPack`·`nextFloor`·`unvisitPack`·`setStageFloor`)에서 1층 복귀를 감지해 아직 'got'인 것만 지운다. 손으로 바꾼 'failed'는 보존.
   - `toggleObserved`가 `{ max, observable }`을 받아 관측 불가 기프트의 지정을 스토어 차원에서 거른다(전에는 UI 버튼만 막았다).

결과: 같은 입력에서 관측 3개 모두 (지정), 1층 1004 · 2층 1005(각 창 1~2), 조합 2층 이후, 「범용 드랍」 줄 없음, 필요 팩 2 · 별빛 320 · 4/4 확보. 1층 입장→돌아가기를 몇 번 반복해도 같은 화면.

## 핵심 규칙

- **지정 관측은 사용자의 결정이다.** 시작 기프트·구제·유연성보다 먼저 적용되고, 팩 기프트·범용 기프트 모두에 걸 수 있으며 관측하면 확정이다.
- **지정을 못 쓰는 경우의 처리**: 관측 불가·한도 초과·계획에 없는 기프트 → `observation-trimmed` 하나로 알림. 보유·미해결 기프트 → 조용히 건너뜀(슬롯 소비 없음).
- **시작 기프트는 범용 요구도 받는다.** 지정으로 이미 관측한 기프트는 다시 잡지 않는다.
- **1층 복귀 = 시작 기프트 기록 취소.** `run.startGifts`는 1층을 떠난 뒤에만 의미가 있고, 저장본에서도 `currentFloor > 1`이고 아직 'got'인 것만 살린다.

## 남은 것

- 시작 풀 기프트를 지정하면 공짜 대신 별빛을 쓴다. 사용자가 고른 것이라 그대로 두었고, UI에서 「시작 기프트로 받을 수 있음」을 알리는 것은 다음 과제.
- 같은 기프트를 두 조합이 각각 필요로 할 때(`count > 1`) 관측 한 번을 두 요구 모두에 적용한다. 데이터상 그런 조합이 드물어 그대로 두었다.
