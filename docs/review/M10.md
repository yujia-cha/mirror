# M10 — 15층 고정 · 반드시/포기 우선순위 · 칸 길이 = 층 수

커밋: `M10a: 옵션 15층·Hard 고정 + 우선순위(반드시/포기)`, `M10b: 시간표 — 칸 고정·팝오버/시트·라벨 정렬`, `M10c: 문서`

## 무엇을 했나

배포된 페이지를 기프트 32개·15층·Hard로 쓴 모바일 스크린샷 2장에서 여덟 가지 문제를 확인했습니다. 층 라벨과 블록이 어긋나고(S1), 블록 높이가 픽업 수에 따라 달라져 칸 길이가 층 수를 뜻하지 않으며(S2), 6~10층에 유동 블록 5개가 서면 글자가 세 줄로 접히고(S3), 시작 칸 관측 타일이 세로로 쌓이고(S4), 미해결 14건이 행마다 버튼을 반복해 화면 두 장을 차지하고(S5), 조합 재료 사유에 원시 id가 보이고(S6), 층 범위·난이도 선택기가 자리만 차지하며(S7), 근사 결과에서 어떤 기프트를 우선할지 개입할 수단이 없었습니다(S8).

이번에는 (1) 앱이 **항상 1~15층·Hard**로 계획하도록 옵션을 고정하고(S7), (2) 기프트마다 **반드시 / 보통 / 포기** 우선순위를 둬 미해결 행에서 바로 바꾸게 했으며(S5·S6·S8), (3) 시간표를 **고정 크기 격자**로 다시 그려 블록의 길이가 정확히 층 구간이 되게 하고 상세는 팝오버·바텀 시트로 옮겼습니다(S1~S4).

## 우선순위 규칙

- 저장 상태는 `priority: Record<giftId, 'must' | 'skip'>`이고 없으면 보통이다. 해제·비우기 시 함께 지운다. 공유 링크(v3)에 포함되고, 옛 링크·저장값의 알 수 없는 값은 버린다.
- **반드시**는 core의 `required: true`로 올라간다. 탐색 목표가 `missedRequired → missedOptional → packCount`이므로 보통 기프트도 최대한 확보하되 충돌하면 반드시가 이긴다. 관측 구제도 반드시 기프트부터 살린다.
- **포기**는 선택을 유지한 채 계획 입력에서 뺀다. 지정 관측이 있었다면 함께 푼다. 요약에 「포기 n」, 미해결 카드 아래 「포기한 기프트 n」에서 되돌린다. 텍스트 복사 마지막 줄에 「포기: …」.
- 대안 루트 탭의 「이 기프트 포기」는 `setPriority(id, 'skip')`이다(M9의 「빼고 확정」은 선택 자체를 지웠다). 대안 후보에서 반드시 기프트는 제외한다 — 단, 모든 기프트가 required인 입력(CLI 기본)에서는 구분할 등급이 없으므로 전부 후보다.
- 근사 결과(탐색 한도)는 그대로다. 반드시/포기로 탐색 폭이 줄어 「근사」가 사라지는 경우가 많다(32개 시나리오에서 포기 2개로 확보 30/30).

## 격자 규칙

- 데스크톱: 열 `84px repeat(15, minmax(0, 1fr))`, 레인 행 `repeat(n, 132px)`. 호버해도 열 템플릿은 변하지 않는다(`grid-animate` CSS 삭제).
- 모바일: 열 `56px repeat(n, minmax(0, 1fr))`, 행 = 시작 `auto` + 층 64px + 자유 병합 40px.
- 블록 = `role="button"` + `aria-haspopup="dialog"` + `aria-label` 「{팩} · {구간} · 기프트 n개 · 자세히」. 안쪽은 팩 이미지 24(모바일 32) + 이름 1줄 + 「고정」/「4~5 · 추천 4」(compact는 「추천 4」) + 아이콘 32 타일. `iconCap(span, layout)`(데스크톱 2/층, 모바일 4/층, compact 1/층)을 넘으면 마지막 자리가 「+n」 칩.
- 상세: 데스크톱은 `pointerenter`/`focus` 150ms 뒤 팝오버(300px, 아래 공간 부족하면 위, 오른쪽 넘치면 우측 정렬), `pointerleave`/`blur`/Escape/바깥 클릭으로 닫힘. 모바일은 탭 → 바텀 시트(`role=dialog` `aria-modal`, 70vh, 닫기 버튼·바깥 탭·Escape). 시트·팝오버는 블록 안에 렌더되므로 자기 클릭을 `stopPropagation`으로 막는다.
- 시작 칸의 관측 타일: 데스크톱은 바로 지정/해제, 모바일은 시트에서 지정/해제.

## 남은 것

- `iconCap`은 측정이 아니라 층 수 기반 상한이다. 1024px 데스크톱에서는 층 열이 60px라 1-층 블록에 아이콘 1개만 온전히 보이고 둘째는 잘린다(팝오버가 대신 보여 준다). 컨테이너 쿼리로 바꾸면 더 정확하다.
- 커서가 이미 놓인 자리에 블록이 새로 그려지면(대안 탭 전환 등) 팝오버가 바로 열린다. 브라우저 동작이라 그대로 뒀다.
- 탐색 한도(`DEFAULT_NODE_CAP`)는 100ms 시간 테스트 때문에 올리지 않았다.
