# M0 — 스캐폴드와 Claude Code 설정

커밋: `M0: 프로젝트 스캐폴드와 Claude Code 설정`

## 무엇을 했나

빈 저장소에 프로젝트 기반을 만들었습니다. 제품 코드는 아직 없고, 이후 마일스톤이 올라탈 골격과 규칙만 있습니다.

- **스택**: Vite 6 + React 19 + TypeScript(strict) + Tailwind 4 + Vitest 3 + ESLint 9
- **CI** (`.github/workflows/ci.yml`): lint → typecheck → test → 데이터 검증 → **데이터 재현성 검사** → build
- **배포** (`.github/workflows/deploy.yml`): main 푸시 시 `VITE_BASE=/<repo>/`로 빌드해 GitHub Pages로
- **Claude Code 설정**: 서브에이전트 5종, 스킬 6종, 훅 4종
- **문서**: `CLAUDE.md`, `docs/research/`(메커니즘 조사 기록·데이터 출처·변경 기록), `data/README.md`

## 읽는 순서

1. `CLAUDE.md` — 디렉터리 규칙과 도메인 규칙 요약. 여기 적힌 규칙이 이후 모든 코드의 전제입니다.
2. `docs/research/mechanics.md` — **게임 지식과 대조해 주세요.** 층·난이도·관측 규칙, 조건 판정 방식, 획득 분류를 여기서 정의했고 코드가 그대로 따릅니다.
3. `docs/research/data-sources.md` — 어디서 데이터를 가져오는지와 라이선스
4. `.claude/skills/md-domain/SKILL.md` — 작업 전에 읽히는 도메인 레퍼런스
5. `.claude/agents/*.md`, `.claude/hooks/*.sh`, `.claude/settings.json`
6. 설정 파일들 (`tsconfig.json`, `vite.config.ts`, `eslint.config.js`, 워크플로)

## 서브에이전트 5종

| 이름 | 담당 | 도구 |
|---|---|---|
| `game-data-researcher` | 게임 규칙·데이터 출처 조사 | 읽기 전용 |
| `data-pipeline-engineer` | `scripts/`, `data/`, `public/data` | 전체 |
| `route-algorithm-engineer` | `src/core`와 테스트 | 전체 |
| `frontend-engineer` | `src/app` | 전체 |
| `qa-reviewer` | 푸시 전 diff 리뷰 | 읽기 + Bash |

각 에이전트 정의에 "무엇을 하지 않는가"를 적어 담당 영역이 겹치지 않게 했습니다.

## 스킬 6종

`md-domain`(도메인 레퍼런스), `update-game-data`(데이터 갱신 런북), `validate-data`(검증 실패 대처), `add-curated-override`(보정 작성법), `route-debug`(루트 재현·회귀 테스트), `deploy-pages`(배포·문제 해결).

## 훅 4종

| 이벤트 | 동작 | 차단 여부 |
|---|---|---|
| SessionStart | `node_modules` 없으면 `npm ci`, 데이터 상태 출력 | 안 함 |
| PostToolUse (편집) | 경로별로 데이터 검증 / 코어 테스트 / 타입 검사 | **차단** (exit 2) |
| PreToolUse (Bash) | `git commit`·`git push` 전 `npm run check` | **차단** (exit 2) |
| Stop | 생성물이 원본보다 오래됐으면 경고 | 안 함 |

PostToolUse 훅은 `public/data`와 `data/raw` 직접 편집도 막습니다(생성물·원본이라서).

## 검증 로그

```
$ npx tsc --noEmit      → 통과
$ npx eslint .          → 통과
$ npm run build         → dist 생성 성공
$ .claude/hooks/post-edit.sh (수동 호출)
    src/app/App.tsx      → typecheck 실행
    public/data/x.json   → exit 2로 차단, "생성물이다" 안내
$ .claude/hooks/session-start.sh → node v22.22.2, 데이터 미생성 안내 출력
```

## 봐 주셨으면 하는 점

1. **`docs/research/mechanics.md`의 규칙이 실제 게임과 맞는지.** 특히 Hard sticky, 평행중첩 진입 조건(1~5층 전부 Hard), EXTREME 관측 불가, 키워드 팩이 전부 Hard 전용이라는 점.
2. **훅이 너무 자주 막지는 않는지.** 편집마다 검사를 돌리므로 느리다고 느끼면 PostToolUse를 타입 검사만 남기고 줄일 수 있습니다.
3. 워크플로 권한이 최소인지 (`deploy.yml`은 pages/id-token/contents:read만).

## 알려진 한계

- `npm audit`에 개발 의존성 취약점 경고가 있습니다(런타임 의존성은 0건).
- GitHub Pages는 저장소 Settings → Pages → Source를 "GitHub Actions"로 한 번 설정해야 합니다.
