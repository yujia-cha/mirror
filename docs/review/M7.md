## 설계 판단

**출격 인원은 규칙 데이터.** `rules.deployment { max: 7, default: 6, verified: false }`를 `data/curated/rules.json`에 두고 `analyseDeck`가 읽습니다. 「최대 7」은 사용자가 지정한 값이라 `verified: false`이고 `_source`에 그렇게 적었습니다. `options.deployed`는 덱 순서를 유지한 채 정리되며, 빈 배열은 「아무도 출격하지 않음」입니다.

**층 창은 검색을 바꾸지 않고 파생.** `FloorPlan.window`는 배정을 고정한 채 같은 팩이 놓일 수 있는 연속 층을 다시 계산합니다(`windowFor`). 다른 필수·핀 팩이 쓰는 층은 제외하므로 화왕지절(Hard 4~5)이 해방된 분노(Hard 5)와 함께 있으면 `{4,4}`로 줄어듭니다. UI는 `from === to`를 고정 블록, 아니면 점선 구간 블록으로 그립니다.

**조합 계승은 빌드 시 파생.** 재료가 정확히 하나의 같은 키워드·상위 등급 결과에만 쓰이면 `gifts[].upgradeOf`가 그 id입니다(76쌍). 진혼처럼 자식이 여럿인 1:N 관계라 UI에서는 상위 행 아래 서브행으로 접고, 상위를 고르면 하위를 `wanted`에서 자동으로 뺍니다. 명세의 `fusion.upgradeOf`가 아니라 최상위 필드로 둔 이유는 범용 재료(`fusion: null`)에도 붙기 때문입니다.

**회색 전용 토큰.** `src/index.css`의 `@theme`에 `--color-*: initial` 뒤 11개 회색 토큰만 두고 `.dark`에서 같은 이름을 덮어씁니다. 확정은 ink 채움 + 체크, 나올 수 있음은 점선 + 물결.

**Hard는 단방향.** 「Hard로 전환」 버튼은 누르면 잠금 pill로 바뀌고 되돌리는 컨트롤이 없습니다. 6층 이상을 고르면 자동으로 잠기고 안내 1줄이 붙습니다. 해제는 「옵션 초기화」뿐입니다.

**가상 목록은 직접.** 행 높이를 프리픽스 합으로 두는 30줄짜리 `useVirtualRows`로 충분해 의존성을 늘리지 않았습니다.

**서체.** Pretendard 선언을 지우고 시스템 한글 폰트(Apple SD Gothic Neo / Malgun Gothic)만 씁니다. 외부 폰트 요청이 없습니다.

## 알려진 한계 · 남은 질문

- 출격 「최대 7」의 게임 내 근거가 없습니다. 확인되면 `rules.deployment.verified`를 올리고 `_source`를 바꾸세요.
- E.G.O가 키워드 판정을 바꾸는 사례 데이터가 없어 E.G.O 슬롯은 보류입니다(명세 「구현 전제」 2).
- `includesSpecial`(특수 화상 등)은 여전히 평가에서 무시됩니다.
- 유동 구간 블록에서 추천 층이 아닌 층을 고르면 조합 `earliestFloor`가 달라질 수 있는데, 시간표는 이를 다시 계산하지 않습니다.
- (M8에서 해결) 창이 「다른 배정 고정」 기준이라 서로 층을 바꿀 수 있는 팩이 고정으로 보이던 문제, 공유 해시가 재로드마다 상태를 덮던 문제, 15층 계획의 시간표 열 붕괴, 하위 기프트 단독 선택 불가 — `docs/review/M8.md`.
- 캔버스의 E.G.O 이름·「+특수 화상」은 샘플입니다.
