## 1. 모바일 — 시트를 닫으면 패널까지 닫히던 버그

### 원인

`useDismiss`는 `document`에 `pointerdown`·`keydown`을 붙인다. 폰 드로어가 이 훅을 쓰는데(`SidePanel.tsx:68`), 상세 시트는 패널이 `@container`라 `createPortal`로 `document.body`에 뜬다. 시트는 드로어 `ref` **바깥**이라 시트 안 어디를 눌러도 드로어가 닫혔다.

`BlockDetail`의 `stopPropagation`은 `click`·`keydown`만 막고 **`pointerdown`을 놔뒀다**. `useDismiss`가 듣는 건 click보다 먼저 오는 pointerdown이라 ✕ 버튼조차 새어 나갔다. 데스크톱은 `open && !desktop` 조건 덕에 무관하다 — 1024px 미만 전용 버그였다.

덱 검색은 이 함정을 이미 알고 손으로 막아 두고 있었다(`DeckStep.tsx`의 `event.stopPropagation()`과 그 주석). 시트에는 그 가드가 없었다.

### 조사 중 나온 것 둘

- **상세 시트 호스트가 둘이었다.** `PlanContext`와 `GiftsStep`(좌측 패널 **안**). 아이템 탭에서 연 시트는 패널과 함께 언마운트됐고, CLAUDE.md의 「`PlanContext.openGift`가 시트를 한 번만 호스팅」과 어긋나 있었다.
- **시트의 Escape는 원래 동작하지 않았다.** `stopPropagation`이 네이티브 이벤트까지 멈춰 document 리스너에 닿지 못했다. 테스트도 없었다.

### 고친 방법

- `useDismiss`에 **모듈 레이어 스택** — 최상위 레이어만 반응한다. `DeckStep`의 수동 우회를 걷어냈다.
- 시트의 Escape를 `DetailSurface`가 직접 처리한다.
- 시트를 `PlanProvider` 한 곳에서만 호스팅한다. 아이템 탭이 쓰던 「조합 재료까지 흡수」 의미를 공용 시트에 맞췄다(전보다 정확해졌다).

## 2. 모바일 패널 = 전체화면 페이지

`fixed inset-0`의 `w-[min(92vw,380px)]` 오버레이 드로어 → 화면 전체를 덮는 페이지. 백드롭도 `aria-modal`도 없고 바깥 누름·Escape로 닫히지 않는다. 열려 있는 동안 셸(`app-shell`)은 `inert`라 배경이 진짜로 비활성이고 포커스 가둠이 공짜로 따라온다.

앱 헤더까지 덮으므로 페이지가 **자기 상단 바**를 갖는다: ←(`panelBack`) + 제목 `<h1>` + 기존 `TabBar`. 반대쪽 패널로는 헤더가 아니라 **페이지 안에서** 간다(빈 루트의 「아이템」 버튼). 세로 여백에 `env(safe-area-inset-*)`.

**뒤로가기 연동**(`usePageHistory`): 페이지와 시트가 히스토리 엔트리를 하나씩 갖고, 뒤로가기가 시트 → 페이지 순으로 닫는다. `pushState`에 URL을 쓰지 않는다 — 공유 링크 해시(`#s=`)와 GitHub Pages 하위 경로를 건드리면 안 된다.

z 사다리를 명시했다: 헤더 30 · 페이지 40 · 시트 백드롭 50 · 시트 60 · 칩 고스트 70.

### 훅이 잡아낸 진짜 버그

`usePageHistory` 단위 테스트가 두 개를 잡았다.

1. **뒤로가기로 닫은 레이어가 자기 엔트리를 아직 갖고 있다고 여겼다.** popstate 리스너가 `owners`에서만 빼고 훅의 토큰은 그대로 둬서, 뒤이어 상태가 따라잡으면 `history.back()`을 한 번 더 불렀다 — 시트를 뒤로가기로 닫으면 아래 페이지까지 닫혔을 것이다. 리스너가 소유 토큰을 직접 비우게 고쳤다.
2. **`history.back()`은 비동기다.** 한 틱 안에서 한쪽을 닫고 다른 쪽을 여는 경우(패널 교체), 새 레이어가 옛 레이어의 popstate를 먹었다. 스스로 부른 pop을 세어 삼킨다.

jsdom은 히스토리 이동을 아예 구현하지 않아(`history.back()`이 popstate를 내지 않는다) 뒤로가기는 `usePageHistory` 단위 테스트에서 popstate를 직접 보내 검증한다. 앱 테스트는 원 버그(시트 ✕·Escape·바깥 누름이 페이지를 남기는지)를 본다.

### 실제 브라우저 확인

크로미움 360·390·430px: 페이지가 화면 전체를 덮고 헤더를 가린다, 시트 ✕·배경·Escape가 시트만 닫는다, 뒤로가기가 시트 → 페이지 → 앱 이탈 순이다, ←로 닫아도 죽은 엔트리가 남지 않는다, 한 틱 안 페이지 교체가 살아남는다.

`@container` 참고: 패널 본문이 컨테이너이고 `@sm:`(384px)은 **콘텐츠 박스** 기준이라 실측 임계값은 뷰포트 약 408px이다. 430px에서 인격 검색이 340px 팝오버가 된다 — 넓은 화면에서 맞는 동작이다.

## 3. 누락 인격 — 정확히 하나였다

「차원찢개」는 **이스마엘이 아니라 이상, id 10116**이다.

### 검증

파이프라인은 아무것도 버리지 않는다(원본 183 → 생성물 183, 필터 자체가 없다). KR 현지화의 재직 대역(10101–11299) id는 184개, 정적 데이터는 183개, **차이는 10116뿐**이다. 나머지 현지화 전용 행 9999(베르길리우스)·40501은 NPC·스토리다.

데이터가 낡은 탓이 아니다. 상류 OpenLethe **최신 커밋**과 게임 자체의 파일 매니페스트(`static-data-info.json`)까지 대조했고, personality·skill·passive 어디에도 10116이 없다. `sources.lock.json`의 파일 목록도 완전하고 최신이었다(매니페스트가 선언하는 17번째 `personality-x1p1c1`은 OpenLethe가 내보내지 않고, 내용도 만우절 400xxx 비재직 행이다).

**이 누락은 이미 감지되고 있었다 — 경고라서 `npm run check`를 통과했을 뿐이다.**

### 백필

현지화 저장소에는 10116의 **공식 스킬 원문**이 있다(`KR/Skills_personality-01.json`, 1011601~1011605). 그래서 KR `Skills_personality-{01..12}.json` 12개를 vendoring하고(`files[]`에 언어 좁히기를 추가해 EN은 받지 않는다), `scripts/lib/derive-text.ts`가 그 문장에서 키워드를 도출한다. 1011604 회피는 방어 스킬이라 빠지고, 남은 넷이 **충전·파열**을 준다.

`data/curated/identities.json`은 **override가 아니라 backfill**이다. 상류가 같은 id를 내보내면 `data:build`가 멈추고 항목을 지우라고 말한다 — 손으로 적은 값이 진짜 데이터를 영원히 가리지 않게.

소속·죄악·공격 유형은 인용할 출처가 없어 **비웠다**. 대가는 정확히 하나다: 소속 조건 기프트는 게임 전체에 9778 통상 작전용 장비뿐이고, 10116을 편성하면 그 조건이 한 명 적게 센다. 없는 근거로 과대약속하는 것보다 낫다. rank 3은 다른 LCE E.G.O 인격(10111·10211·11215)이 모두 3인 데 따른 추정이고, rank는 정렬·별 표시 전용이라 루트 계산에 들어가지 않는다 — 추정임을 `_source`에 적었다.

### 캘리브레이션 — 도출을 믿어도 되는 이유

도출 규칙을 정적 데이터가 **둘 다 있는 121명**에게 돌렸다(`tests/text-derivation.test.ts`).

| | |
|---|---|
| 대조 가능 | **121 / 183** (현지화 미러가 12파일만 내보낸다 — 테스트가 이 한계를 그대로 단언한다) |
| **없는 키워드를 지어낸 경우** | **0 / 121** |
| 계획이 읽는 값 일치 | **112 / 121** |
| 고정된 예외 | 9 — 전부 텍스트가 **덜** 말하는 쪽 |

정확한 스킬 **개수**가 아니라 계획에 도달하는 값(`{키워드 → (기본>0, 특수>0)}`)으로 맞춘다. `deck.ts`가 스킬 수와 무관하게 인격 단위로 세고 칩에 개수를 안 쓰므로, 개수를 맞추는 건 아무도 못 보는 차이를 쫓는 일이다.

**지어내지 않는다**는 한쪽 성질이 10116의 값을 내보낼 근거다. 처음엔 한 명(10514 로보토미 E.G.O:: 호넷【변조】)이 반대 방향으로 틀렸다 — 정적은 특수 탄환만인데 텍스트는 기본 탄환도 주장했다. 원인은 `MeursaultSporeBulletReloading`, 포자탄의 재장전 상태 버프인데 특수 변형으로 선언되지 않은 것이었다. 「선언된 특수 탄환과 같은 계열(마지막 `Bullet`까지의 접두사가 같고, 그 접두사가 맨 `Bullet`이 아닌 것)은 기본 탄환이 아니다」로 좁혔다. 평범한 탄환 id(`Bullet`·`BulletLament`·`AccelBullet`)는 계열 접두사가 없어 그대로 남는다.

남은 9명은 버프 id로만 부여하고 문장에 한국어 이름이 없는 경우다. 예외 0을 목표로 튜닝하지 않았다 — 쫓아가면 정밀도를 잃는다. 예외표는 **집합 동일성**으로 단언해서 새 불일치도, 낡은 항목도 실패시킨다.

### 다시 조용히 지나가지 못하게

- 현지화-정적 괴리: `warn` → **`strict` 에러**. 메시지가 `data/curated/identities.json`을 가리킨다.
- 백필 정직성: 현지화에 있는 id인가 / 정적에 없는가 / 생성물에 들어갔는가.
- 죄인 완전성: 12죄인이 모두 있고 각자 최소 10명(현재 최소 14). 파일 하나가 빠져도 합계 하한만으로는 통과하던 구멍.

가드가 진짜 도는지 손으로 확인했다: 10116 항목을 지우면 `data:validate`가 **에러**, `10101`을 넣으면 `data:build`가 **실패**.

## 검증

`npm run check` 통과(345 테스트). `data:build` 두 번 돌려 출력이 같은 것(CI의 재현성 게이트와 같은 조건)까지 확인했다.

## 남은 것

- 상류가 10116을 내보내면 `data/curated/identities.json`에서 지운다 — 빌드가 알려 준다.
- 소속을 채우려면 인게임 확인이 필요하다. 다른 LCE E.G.O 인격은 전부 `['LIMBUS_COMPANY','LIMBUS_COMPANY_LCE']`지만 추정이라 적지 않았다.
- `usePullGesture`의 `swallowNextClick()`도 click만 삼키고 pointerdown은 놔두는 같은 종류의 함정이다. 이번에 드러난 증상은 없었다.
