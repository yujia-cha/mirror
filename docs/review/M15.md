# M15 — 아이템 격자 · 덱 기본값 · 패널 너비

커밋: `M15a: 덱 기본값 LCB · 검색 다중 선택 · 무대 헤더 버튼 삭제`, `M15b: 아이템 패널 격자 — 배지 제거 · 조건 「진동 3/5」 · 상세 시트 · 얽힘`, `M15c: 패널 너비 드래그 · 덱 검색 여러 낱말 OR · 편성 전체 키워드`

시안: https://claude.ai/code/artifact/5711d43c-5189-4f03-9d79-233fbbbba3fd (아트보드 A1·A2·B~F). 사용자가 **격자 A**(아이콘 32 + 이름 + 조건 한 줄)를 골랐다.

## 무엇을 했나

사용자 지시 9가지 + 진행 중에 들어온 3가지.

1. **덱 기본값** — 처음 열면 12칸이 LCB 수감자로 차 있다(출격 6). `defaultDeck()`이 `LIMBUS_COMPANY_LCB` 소속을 데이터에서 골라내므로 id를 코드에 박지 않는다. 저장된 덱·공유 링크가 있으면 그쪽이 이기고, 「기본 덱」 버튼으로 언제든 되돌린다.
2. **검색 다중 선택** — 한 명을 골라도 목록과 검색어가 남는다. 이미 덱에 있는 줄은 체크 + `aria-pressed`, 다시 누르면 빠진다. Esc는 목록만 닫는다(폰 드로어까지 닫히던 것을 막았다).
3. **무대 헤더 버튼 삭제** — 「이전 층」·「입장하지 않음」이 사라졌다. 뒤로는 층 스트립, 앞으로는 「다른 팩 입장」 카드와 팩 영역의 「다음 층」. `prevFloor`가 하던 프런티어 후퇴는 `setStageFloor`로 옮겼다.
4. **조합식 접기** — 상세 시트의 「조합식」은 `<details>`이고 기본으로 닫혀 있다.
5. **얽힘** — 같은 재료를 먹는 조합 목표 둘을 🔗로 표시하고, 시트에 무엇이 겹치는지 적는다. 막지는 않는다(재료를 두 번 주우면 둘 다 된다). 예: 장관 × 부동 → 녹슨 칼자루.
6. **섹션 접힘 버그** — 「지금 덱으로 활성」·「거의 활성」 헤더에 토글이 연결되어 있지 않았다(`onToggle` 미전달). 셋 다 접힌다.
7. **배지·티어 텍스트 제거** — 포함/확정/가능/조합/시작·Hard 배지, 행의 「T{n}」, 키워드 이름, 「+n」 부족 힌트, 진행 바를 없앴다. 티어는 아이콘 모서리 칩만 남는다. 조건은 「진동 3/5」로 줄인다.
8. **상세에 조합식 + 설명** — 획득 경로 한 줄, 조건 전부(짧은 값 + 문장), 효과 전문, 조합식, 얽힘, 「재료도 목표」가 한 시트에 있다.
9. **격자** — 리스트 행을 타일 격자로 바꿨다(`auto-fill minmax(64px,1fr)`). 아이콘을 누르면 목표, 이름을 누르면 시트.
10. **패널 너비 드래그** — 패널과 무대 사이 구분선을 끌어 260~560px로 조절하고 기기에 저장한다. 두 번 누르면 336px, 화살표 키로 16px씩.
11. **덱 검색 OR** — 「화상 침잠」이면 둘 중 하나라도 가진 인격이 모두 나온다(30 + 40).
12. **편성 전체 키워드** — 덱 요약 칩이 「화상 5/7」처럼 출격과 편성 12인을 함께 보여 준다. 대기 인원만 가진 키워드도 칩으로 나온다.

## 핵심 규칙

- **타일은 두 개의 버튼이다.** 아이콘 = 목표 토글(`aria-pressed`), 이름 = 상세 시트. 조합 계승 자식은 부모를 고르면 잠긴다(disabled + 눌린 상태).
- **얽힘은 경고가 아니다.** 계획을 막지 않고 사실만 알린다. 재료가 한쪽의 재료이기도 하면(진혼 ⊃ 요리 비법 전서) 얽힘이 아니라 포함이므로 표시하지 않는다.
- **시트는 `document.body`로 포털한다.** 패널이 `@container`라 그 안의 `position: fixed`는 패널 기준이 된다(M14의 transform 문제와 같은 부류).
- 무대 헤더에는 이제 버튼이 없다. 층 이동은 스트립·카드·팩 영역이 전부다.

## 남은 것

- 기본 LCB 덱에서는 조건부 기프트가 거의 다 「기타」로 간다(활성 0 · 거의 활성 0). 처음 보는 화면이 비어 보이므로, 덱을 채우라는 안내나 기본 접힘 규칙을 손볼 여지가 있다.
- 타일 이름은 2줄에서 잘린다(말줄임 없음). 긴 이름은 시트나 툴팁으로 확인해야 한다.
- 얽힘은 지금 「선택한 목표들」 사이만 본다. 재료를 목표로 삼지 않은 경우(`resultOnly`)의 소모는 계획에는 반영되지만 표시는 하지 않는다.
- 시안의 얽힘 예시(달의 기억 × 진혼)는 설명용이었다. 실제 데이터에서 달의 기억의 재료는 조각·기억 드롭이라 조합끼리 겹치지 않는다.
