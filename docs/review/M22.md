# M22 — 복사 버튼 아이콘화 · 숫자 글꼴 · 「반드시」가 확보를 줄이던 문제 · 루트 로직 문서

커밋: `M22: 「반드시」가 확보를 줄이던 탐색 정렬 수정 · 숫자 글꼴 Nunito · 복사 버튼 아이콘만 · 루트 계산 문서`

## 무엇을 했나

사용자 지시 넷. 3번이 본체다.

### 1. 「반드시」로 올렸더니 확보가 줄던 문제 (지시 3)

제보: 목표 32개가 전부 「보통」일 때는 32/32인데, 데스페라도(9235) 하나만 「반드시」로 올리면 30/32가 된다. 반드시로 올려도 루트가 같아야 한다는 지적이 맞다.

공유 링크를 풀어 앱과 같은 입력으로 재현했다.

| 입력 | 수정 전 | 수정 후 |
|---|---|---|
| 전부 보통 | 32/32 | 32/32 |
| 데스페라도만 반드시 | **30/32** (흘러내린 엔케팔린·안식이 `pack-conflict`) | 32/32 |
| 전부 반드시 | 32/32 | 32/32 |

**원인은 탐색의 후보 방문 순서**(`src/core/search.ts`)였다. 정렬이 `required` → 슬롯 수 순이라, 필수 깃발 하나가 제약과 무관하게 맨 앞으로 끌려 나왔다. 이 크기의 입력은 노드 상한(20만)에 걸리는 근사 탐색이라 **방문 순서가 곧 결과**다. 전부 같은 깃발이면 정렬이 「슬롯 적은 것 먼저」(MRV)로 떨어져 완전해를 찾는데, 하나만 필수면 순서가 흐트러져 더 나쁜 국소해에 멈췄다. 주석은 원래 「가장 제약이 심한 것 먼저」라고 적혀 있었으니 코드가 주석을 배신하고 있었던 셈이다.

수정: 정렬을 **슬롯 수 → 필수 → id**로 돌렸다. 우선순위는 애초에 정렬이 아니라 **목적 함수**(`missedRequired` → `missedOptional` → `packCount` → `floorSum`)가 지킨다. 그래서 진짜로 다 담을 수 없는 상황에서는 반드시가 여전히 이긴다 — 1~5층으로 좁힌 충돌 케이스에서 확인했다(보통이면 버려지고 반드시면 확보된다).

곁가지 하나: **`scripts/route-cli.ts`의 `--share`가 `priority`·`fusionGoal`·출격 인원을 버리고 모든 기프트를 `required: true`로 만들고 있었다.** 제보를 재현하는 도구가 제보 상태를 재현하지 못해, 이번 건도 처음엔 재현되지 않았다. 앱의 `plannedGifts()`를 그대로 쓰도록 고쳤다.

### 2. 숫자 글꼴 (지시 2)

앱의 숫자는 전부 `font-mono`인데 **웹폰트를 하나도 싣지 않아** 기기 기본 고정폭 글꼴이 나오고 있었다(9~11px에서 뭉갠다). **Nunito**(SIL OFL) latin 가변 woff2 39KB를 `src/assets/fonts/`에 자체 호스팅하고, 새 토큰 `--font-num`으로 숫자 자리 25곳(클래스 23 + 노선도 SVG 2)을 옮겼다. 한글이 섞인 조건 칩은 Nunito에 한글이 없어 글자마다 기존 글꼴로 폴백되므로 **숫자만** 둥글어진다. 글꼴을 바꾸고 싶으면 `--font-num` 한 줄만 고치면 된다.

경로는 `src/assets/`에 두어 Vite가 해시를 붙이고 base를 다시 쓰게 했다 — GitHub Pages 하위 경로 빌드에서 `/mirror/assets/nunito-latin-*.woff2`로 나오는 것을 확인했다(`public/`에 두고 절대 경로를 쓰면 이 경로가 깨진다).

### 3. 복사 버튼 (지시 1)

「전체 루트」의 복사 버튼에서 글자를 빼고 아이콘만 남겼다(35×28). 이름은 `title`·`aria-label`로 남아 툴팁·스크린 리더·테스트가 계속 찾는다. 누른 뒤의 토스트(「복사했습니다」)가 피드백을 맡는다.

### 4. 루트 계산 문서 (지시 4)

`docs/route-algorithm.md` — 사용자용 한국어 문서. 11단계 파이프라인, 조합이 재료로 펼쳐지는 규칙, 팩 탐색이 층이 아니라 기프트를 기준으로 도는 이유와 노드 상한(「근사 결과」의 뜻), **「반드시」가 실제로 하는 일 셋과 하지 않는 일**, 관측 슬롯이 쓰이는 순서, 미해결 8종·경고 표, 숫자를 오해하지 않는 법, 알려진 한계. 이번 사고를 사례로 그대로 실었다. `README.md`·`CLAUDE.md`에서 가리키고, `route-debug` 스킬에 `--share`가 이제 우선순위까지 재현한다는 점을 적었다.

## 핵심 규칙

- **우선순위는 탐색 순서를 바꾸지 않는다.** 순서는 「제약이 심한 것 먼저」뿐이고, 반드시는 목적 함수·관측 구조·대안 루트 후보에서만 작동한다.
- **반드시로 올려도 확보 수는 줄지 않는다.** 회귀 테스트가 지킨다.
- **공유 링크는 화면과 같은 입력이어야 한다.** CLI가 이 계약을 깨면 제보를 재현할 수 없다.
- **숫자는 `--font-num` 하나로 관리한다.**

## 검증 로그

- `npm run check` 통과(322 tests, 신규 2). 데이터 파이프라인 무관, `public/data` 변경 없음.
- 새 회귀 테스트는 **예전 정렬에서 실제로 실패한다**(스크래치 복사본에 옛 정렬을 되돌려 실행: `expected 30 to be 32`). 13개짜리 축소판으로는 상한에 걸리지 않아 통과해 버리므로, 제보의 32개 목표를 그대로 테스트에 넣었다(5회 계획, 약 0.6초).
- 우선순위 보존: 1~5층으로 좁힌 충돌에서 데스페라도 반드시 → 확보, 보통 → 버려짐(수정 전후 동일).
- CLI: `npm run route -- --share '<링크>'`가 기본·반드시 링크 모두 앱과 같은 32/32·필요 팩 11·별빛 810.
- 브라우저(vite preview + playwright-core, 1280×900): woff2 200 한 번, `document.fonts.check('12px Nunito') === true`, 층 칸의 `font-family`가 `Nunito, …`. 복사 버튼 글자 없음·툴팁 「텍스트 복사」. 콘솔 에러 0.
- `VITE_BASE=/mirror/` 빌드에서 폰트 URL이 `/mirror/assets/...`로 다시 쓰이는 것 확인.

## 남은 것

- **두 조합이 같은 재료를 각각 필요로 할 때 계획은 층을 한 번만 확보한다**(`Requirement.count`가 계산에 쓰이지 않는다). 지금은 아이템 화면의 「얽힘」 잠금이 이 상황을 막고 있다. 다음 마일스톤 후보.
- 노드 상한이 20만 고정이라 목표 수에 따라 늘지 않는다. 목표가 아주 많으면 여전히 「근사 결과」다.
- `via: 'fusion'`과 `observation-budget` 미해결 사유는 타입에만 있고 만들어지지 않는다(죽은 값).
