# M11 — 노선도 · 팩 카드 · 팩 충돌 카드

커밋: `M11a: 팩 단위 선택 — preferredPacks, 충돌 그룹, 포기한 팩 사유, 팩 옵션 검증`, `M11b: 노선도·팩 카드·팩 충돌 카드`, `M11c: 문서·검증`

시안: https://claude.ai/code/artifact/6a034f01-67dd-4106-af5d-8d53dd439184 — v2 1페이지 「B+E 확정안」(노선도 B + 팩 충돌 카드 E), 2페이지는 보류한 방향.

## 무엇을 했나

미해결 카드는 기프트 한 줄씩이었고, 사용자가 실제로 고르는 단위인 **팩**이 보이지 않았습니다. 시간표는 칸 길이가 층 수를 뜻했지만 같은 창의 팩이 레인마다 흩어져 「어느 순서든 된다」는 사실이 드러나지 않았습니다.

이번에는 (1) core에 **팩 단위 선택**(「이 팩으로」 `preferredPacks`, 「이 팩 포기」 `bannedPacks`)과 **충돌 그룹**(`conflictGroups`: 이어진 경합 층 + 후보 팩 + 각 팩이 가져올 기프트)을 두고, (2) 루트를 **노선도**로 그려 창이 같은 팩은 한 세그먼트에 이름만 나란히 적고 창이 일부만 겹칠 때만 레인을 나눠 추천 층을 찍으며, (3) 팩을 게임 비율(8:15) **카드 + 아래 이름**으로 보이고 클릭하면 **그 팩의 기프트**와 포함/포기 조치를 담은 시트를 열고, (4) 미해결 카드를 **팩 충돌 카드**로 바꿨습니다.

## 표시 규칙

| 상황 | 노선도 |
|---|---|
| 팩이 한 층에 고정 | 역 위 검은 블록, 카드 「{k}층 고정」(실선 테두리) |
| 창 안 어느 층이든 되는 팩 | 점선 세그먼트, 카드 「{a}~{b}층 중 한 층」. **추천 없음** |
| 창이 정확히 같은 팩 여러 개 | 세그먼트 하나, 카드에 이름 전부 「{a}~{b}층 · {n}팩 · 어느 층이든」 |
| 창이 일부만 겹치는 팩 | 레인 분리, 플래너 배정 층에 추천 점, 두 창이 다 덮는 역은 반쪽 원 「둘 중 한 팩만」, 카드 「{a}~{b}층 · 추천 {k}」 |
| 아무 팩도 배정되지 않은 층 | 빈 역(텍스트 복사에는 「{a}~{b}F: 자유」) |

창은 core의 `windowFor`가 「다른 팩이 옮겨 준다」고 가정하고 계산하므로 2~3층 팩과 3~4층 팩은 서로 겹친 창을 받는다. 그래서 「부분 겹침」이 생기고, 그때만 추천 층이 의미를 가진다.

## 팩 충돌 카드

- 그룹 = `conflictGroups`의 이어진 경합 층(예 「11~15층 · 자리 5개에 팩 6개」). 후보 = 그 층에 배정된 팩 + 충돌 기프트의 팩. 각 후보에 가져올 기프트(재료는 원하는 결과로 환원, 범용 드랍 제외)와 「포함 · {k}층」/「루트에 없음」 배지.
- 「이 팩 포기」 → `bannedPacks`: 그 팩의 전용 기프트는 `pack-banned` 사유로 미해결, 빈자리에 미포함 팩이 들어온다. 「되돌리기」로 복귀. 반드시 기프트의 유일 팩이면 확인 문구.
- 「이 팩으로」 → `preferredPacks`: 플래너가 그 팩을 반드시 넣는다(원하는 기프트가 없어도). 다른 팩이 밀려나면 그 기프트가 미해결로 남는다. 자리가 없으면 `pack-option-dropped` 경고.
- 그 외 미해결(조건·범위·조합 재료)은 M10의 행과 버튼 그대로.

## 남은 것

- 데스크톱 라벨 카드는 첫 렌더에서 141px로 추정하고 곧바로 재측정한다. 이미지 로드로 높이가 바뀌면(외부 이미지 훅) 한 프레임 겹칠 수 있다.
- 32개 시나리오에서는 4~15층이 하나의 충돌 그룹으로 묶인다(경합 층이 이어져서). 층 밴드별로 나누면 읽기 쉬울 수 있다.
- 폰에서 미해결 카드가 노선도보다 위에 온다(M10 순서 유지).
- 런 진행 모드(수집 완료/실패, 방문 층, 앞으로 갈 수 있는 팩)는 M12.
