# M26 — 거울 던전 8 대비: MD 교차검증 · 폴백 · 직접 추출 경로

커밋: `data: 거울 던전 데이터에 폴백 계층과 교차검증 · 직접 추출 경로`

M25에서 인격 출처는 고쳤지만 거울 던전 데이터는 여전히 OpenLethe 하나에 매달려 있었다. 사용자 지시: 「거울던전 8을 대비한 출처를 찾아 달라, 또는 수기 데이터 입력 시스템을 구상해 달라.」

## 0. 먼저 정정

앞선 문서에 「MD8이 오면 앱 전체가 멈춘다」고 적었는데 **틀렸다. 멈추지 않고 조용히 틀려진다.** 파이프라인은 `mirror-dungeon-common-data-*.json` 중 `currentDungeonId`가 가장 큰 것을 고르므로(`scripts/lib/raw.ts`), md8 파일이 안 들어오면 **계속 MD7을 계획한다** — 게임에 없는 시즌을, 에러도 경고도 없이. 멈추는 편이 차라리 나았다.

뒤집으면 좋은 소식이다: 시즌 선택이 데이터 주도라 md8 파일이 **어떤 경로로든** 들어오면 파이프라인이 알아서 집는다. 이 성질이 아래 설계의 토대다.

## 1. 답은 「또는」이 아니라 「둘 다」였다

살아 있는 MD 데이터 출처는 **`eldritchtools/limbus-assets` 하나뿐**이다. 원본 스키마 미러는 2025년에 전멸했고(`flaglow`·`Hiro420`), 스키마가 완벽했던 `monthofjune/limbus_data`는 2026-07-27에 멈췄다. 공개된 무인증 공식 경로는 없다 — CDN은 게임 설치본에서 뽑은 빌드 토큰이 필요하고 거기엔 현지화뿐이며, 서버 API에도 데이터 엔드포인트가 없다.

그리고 **그 하나로도 완전 대체는 안 된다.** 현 시즌 데이터로 전수 대조한 결과:

| 항목 | 결과 |
|---|---|
| 팩 층 제한 | ✅ 선택 가능한 팩 전수 일치 |
| 고정 조합 레시피 | ✅ **59/59** |
| 시작 기프트 풀 | ✅ **10/10** |
| 기프트 등급·키워드·죄악 | ✅ 전수 일치 |
| 팩 전용 기프트 | ⚠️ 포함 관계(클리어 보상이 섞임) |
| **팩별 범용 기프트 풀** | ❌ **없다** — 116팩이 78종의 서로 다른 풀을 쓰므로 추론 불가 |
| 가격 · 관측 목록 · 던전 상수 | ❌ 없다 |
| Hard 전용 | ⚠️ 파생값, 거짓 음성 6건 |

그래서 **세 층**으로 만들었다: 정적 > 폴백 > 직접 추출.

## 2. 교차검증 — 지금 당장 값을 낸다

`validate-data`에 여섯 가지 대조를 넣었다(전부 경고 — 저쪽이 덜 아는 축도 있다). 기준선을 고정해 표가 썩지 않게 한다.

| 검사 | 기준선 |
|---|---|
| 팩 명부 | 3001(히든 팩) 하나 |
| 기프트 명부 | 10개 — 9242 + 9831~9839 |
| 층 가용성 · 조합 레시피 · 시작 풀 · 등급 | **전부 0** |

**이 여섯 줄이 MD8의 첫 경보다.** 새 팩이 저쪽에 들어오는 순간 명부가 어긋난다. 가짜 팩·가짜 층·가짜 레시피를 넣어 셋 다 발화하는 것을 확인했다.

명부 기준선의 10개는 「우리 데이터에 없는 것」이 아니라 **빌드가 일부러 거르는 것**이다 — 9831~9839는 거던에서 선택 불가한 팩 1122 전용이고, 9242는 히든 팩 전용이다. 빌드는 「이번 시즌에 도달 가능한 경로가 있는 기프트」만 내보낸다.

**덤**: 저쪽 층 지도가 히든 팩 3001을 `hard 3·4·5·6-10`으로 명시한다 — 우리 `rules.json`의 미검증 커뮤니티 보고와 **정확히 일치**한다. 층은 독립 확인됐지만 확률 0.02%는 여전히 근거가 없으므로 `verified`는 건드리지 않았다.

## 3. 폴백 — 원본 「모양」으로 합성한다

핵심 설계: 완성된 `ThemePack`/`Gift`가 아니라 **`RawThemePack`/`RawGift`를 합성**한다(`scripts/lib/derived-md.ts`). 그러면 층 가용성 도출·기프트 풀·획득 분류·충돌 그룹 등 **하류 전부가 한 줄도 안 바뀌고** 돌아가며, 폴백이 실제 경로에서 멀어질 수 없다.

- 층 → `exceptionConditions`(0-기준, `dungeonIdx` 0~3)
- 등급 → `tag: ['TIER_4']` (`tierFromTags`가 그대로 읽는다)
- 이름은 현지화 우선, 없으면 파생 미러의 영문 이름 — 패치 직후 며칠간 이름 없는 팩이 나오지 않게

**현 시즌에서는 아무것도 하지 않는다**: 정적 데이터가 있으므로 생성물이 **한 바이트도 안 바뀐다**(확인함).

### 폴백이 잠든 채 썩지 않게

MD8은 아직 없으니 이 코드는 테스트되지 않은 채 잠들 위험이 크다. 그래서 `tests/md-fallback.test.ts`가 **현 시즌 데이터로** 검증한다 — 인격 도출을 121명으로 캘리브레이션한 것과 같은 방식. 합성한 원본 레코드를 **실제 프로덕션 도출 함수에 되먹여** 층·등급을 왕복시키므로 인코딩 실수가 바로 드러난다.

마지막 테스트는 **못 하는 것을 못 박는다**: 범용 풀·가격·관측 목록이 저쪽에 없다는 것을 단언한다. 저쪽이 나중에 그것들을 담기 시작하면 이 테스트가 실패하고, 그때 폴백을 온전하게 만들면 된다.

### 실제로 MD8을 흉내 내 봤다

파생 미러에 가짜 팩 1999(hard 2·3층)와 전용 기프트 둘을 주입했더니:

- 빌드가 `backfilled from the derived mirror: 1 pack(s), 2 gift(s)`를 찍고
- 팩이 층 `hard [2,3]`·전용 기프트 2개로 정확히 들어오고
- 기프트가 등급 4/EX·화상/호흡·분노/우울로, `packLimited`로 분류되고
- **검증이 에러로 막았다**: 「범용 기프트 풀이 없다 — 범용 기프트를 이 팩으로 계획할 수 없다」

마지막이 요점이다. 반쯤 맞는 계획을 내놓는 대신 못 한다고 말한다.

## 4. 직접 추출 — `npm run data:import`

팩별 범용 풀은 커뮤니티 출처로 못 얻는다. 남은 길은 원본 static-data를 한 번 얻는 것뿐이다.

```bash
npm run data:import -- <추출한 폴더>          # 미리보기
npm run data:import -- <추출한 폴더> --write   # 적용
```

- 폴더 구조와 무관하게 파일명으로 찾는다
- **쓰기 전에 검사한다** — JSON인지, 기대하는 모양인지. 엉뚱한 폴더를 가리키면 아무것도 안 바뀐다(확인함)
- **새 시즌 파일을 찾아 알려 준다**. lock은 고치지 않는다 — 사람이 봐야 한다
- 왕복 검증: 현재 `data/raw/static`을 입력으로 주면 82개 전부 unchanged

**검증할 수 있는 범위를 분명히 한다**: 스크립트는 「추출된 폴더 → `data/raw`」 구간만 맡는다. 추출 자체(UnityPy·catalog)는 사용자 PC에서 돌아야 하고, 공식 CDN은 이 환경의 egress가 막아 **끝까지 검증할 수 없다**.

## 5. 중간에 잡은 것 둘

- **`dataVersion`이 파생 미러를 세지 않았다.** `inputsFingerprint()`가 `data/raw/derived`를 걷지 않아, M25에서 파생 데이터를 입력으로 삼은 뒤로 **그것이 바뀌어도 dataVersion이 그대로**였다. M25에서 내가 만든 구멍이고, 이번에 막았다.
- 시즌 번호 추출 정규식이 `personality-08.json`을 「시즌 8」로 읽어 새 시즌 탐지가 먹통이었다. 거울 던전 파일로 한정해 고쳤다.

## 6. 검증

`npm run check` 통과(355 테스트). 현 시즌 생성물은 `dataVersion` 외 **무변화**, 재현성 확인.

## 7. 남은 것

- **직접 추출은 게임이 설치된 PC가 필요하다.** 그것이 불가능하면 새 시즌은 **팩 한정·조합·시작 기프트까지만** 계획할 수 있고 범용 기프트 경로는 꺼진다. 그 상태를 조용히 넘기지 않는 것이 이번 설계의 요점이다
- 가격·관측 목록·던전 상수·Hard 전용 보정을 `data/curated/`로 적는 **수기 입력 시스템은 만들지 않았다**(사용자와 합의한 범위 밖). MD8의 실제 모양을 본 뒤에 하는 편이 낫다
- `monthofjune/limbus_data`는 스키마가 우리에게 가장 잘 맞았는데 7월에 멈췄다. MD8 때 되살아났는지 확인할 가치가 있다(`raw.githubusercontent.com/monthofjune/limbus_data/main/meta.json`의 `revision`)
