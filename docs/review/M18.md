# M18 — 우측 루트 패널의 목표 기프트 격자 · 타일에서 기프트 정보 열기

커밋: `M18: 우측 루트 패널 목표 기프트 격자 — 추적기식 획득 토글, 무대 팩 타일과 연동 · 타일 길게 누르기/ⓘ/우클릭으로 기프트 정보`

## 무엇을 했나

사용자 지시 2가지.

1. **목표 기프트 격자** — 우측 「전체 루트」 탭 상단(요약 행 바로 아래)에 「목표 기프트」 카드를 두었다. 선택한 기프트 **전부**(포기 포함, 포기는 링 없이 흐리게)를 `wanted` 순서대로 T4 추적기와 같은 `GiftTile`로 보여 주고, 조합 목표 뒤에는 `←` 와 함께 플랜이 고른 레시피의 **재료 타일**을 붙였다(무대 팩 타일이 보여 주는 것이 바로 재료라서 1:1로 맞는다). 오른쪽 카운터는 「획득/전체」. 상태는 무대 입장 팩·추적기와 **같은 `run.giftStatus`** 를 읽고 쓰므로 어디서 표시하든 즉시 맞고, `planInputFor`가 그 상태를 `ownedGifts`/`unobtainableGifts`로 넘기니 격자에서 재료를 표시하면 루트도 곧바로 다시 계산된다(예: 서릿발 발자국 재료 귀신 들린 신발을 표시하면 공장 자동화가 루트에서 빠진다). 상호작용은 추적기와 같다: 누르면 획득 ↔ 해제, 실패는 층을 떠날 때의 자동 실패만 만들고 실패 타일을 누르면 획득. 달의 기억 안내는 `FusionNotice`로 뽑아 추적기와 공유했다.
2. **타일에서 기프트 정보** — 무대 입장 팩의 획득 표시 타일(그리고 새 격자·추적기 타일)에서 기프트 상세를 볼 수 있다. 좌클릭은 이미 획득 토글이라, **1초 길게 누르기**(`useLongPress`, 놓을 때의 클릭은 삼킨다)·**우클릭**·타일 모서리의 **ⓘ 버튼**(클릭·키보드) 세 가지가 같은 시트를 연다. 시트는 아이템 탭이 쓰는 `GiftDetailSheet` 그대로(우선순위·관측 지정·조합 목표 조작 포함)이고, `PlanProvider`가 한 번만 호스팅해 `openGift(id)`로 어디서든 연다(`createPortal`로 body에 붙으므로 패널 `@container` 문제 없음). 조합 계승 자식 계산은 `lib/upgrade-children.ts`로 옮겨 아이템 탭과 시트 호스트가 공유한다.

## 핵심 규칙

- **획득 기록은 한 곳(`run.giftStatus`)** — 무대·격자·추적기는 모두 그 기록의 뷰다. 새 표면을 만들 때도 같은 규칙: `useApp(s => s.run.giftStatus)` + `setGiftStatus`.
- **격자는 `wanted` 전체**를 보인다(`PlanContext.goals`는 포기를 뺀 계획 대상이라 쓰지 않는다). 재료는 `shown.fusions`의 레시피에서 한 단계만 펼친다.
- **길게 누르기는 클릭을 대신하지 않는다**: 1초 안에 떼면 그대로 토글, 1초가 지나면 정보가 열리고 놓을 때의 클릭은 `consume()`으로 버린다. 훅은 전역 `setTimeout`을 쓴다(`window.setTimeout`은 vitest 가짜 타이머가 잡지 못한다).

## 검증 로그

- `npm run check` — lint·typecheck·테스트 298개(신규 6)·data:validate 통과.
- Chromium 스모크: 목표 4개(프레스티지 카드·서릿발 발자국·생강꽃 가지·깨진 안경) → 격자에 4행 + 서릿발 재료 2개; 1004 입장 후 무대에서 귀신 들린 신발 표시 → 격자 재료 타일 획득; 격자에서 해제 → 무대도 해제; 돌아가기 → 둘 다 초기화; 타일 1초 누름 → 상세 시트.

## 남은 것

- 격자 타일에 「어디서 얻는가」(층·팩·관측·시작 기프트)를 한 줄로 붙이는 도우미(`giftSource`)는 아직 없다. 노선도가 그 역할을 하지만 타일 툴팁에 넣으면 더 빠르다.
