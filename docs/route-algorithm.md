# 루트는 이렇게 계산된다

이 앱이 「어느 층에서 어느 팩에 들어가라」를 어떻게 정하는지 적은 문서다. 코드를 읽지 않아도 결과를 해석할 수 있게, 그리고 **왜 내 예상과 다른 답이 나왔는지** 스스로 따져 볼 수 있게 쓴 것이다.

계산은 전부 `src/core/`에 있고 순수 함수다 — 같은 입력이면 언제나 같은 출력이 나온다. 브라우저에서 돌든 `npm run route`로 돌든 결과가 같다.

## 1. 한눈에

```
입력                          계산                                   출력
────────────────   ──────────────────────────────   ──────────────────────
덱 12인 · 출격 7인   1. 옵션 정리                      층별 계획(1~15)
고른 기프트          2. 조합을 재료로 펼치기             · 어느 팩에 들어갈지
관측 지정            3. 루트가 필요 없는 것 걸러내기       · 그 층에서 주울 기프트
반드시/보통          4. 지정 관측 반영                   · 관측이 필요한지
포함·포기한 팩       5. 시작 기프트 고르기                조합 일정(몇 층 이후)
런 진행 상태         6. 팩 탐색 + 추천 관측              미해결 목록(이유별)
                   7. 조합 일정 · 포기할 재료 정리       경고
                   8~11. 층 계획 · 경고 · 조립         「필요 팩 N · 확보 M/T」
```

## 2. 열한 단계

`planRoute()`는 아래 순서로 한 번 훑는다. 앞 단계가 정한 것은 뒤 단계가 뒤집지 않는다.

1. **옵션 정리** — 알 수 없는 팩 지정, 그 층에 나오지 않는 핀, 서로 모순되는 지정(포기 + 포함)을 걸러낸다. 6층 이상을 계획하면 평행중첩 조건 때문에 **1층부터 Hard로 강제**된다. 걸러낸 것은 경고로 알린다.
2. **무엇을 실제로 주워야 하는가** — 고른 기프트를 **주울 수 있는 물건의 목록**으로 바꾼다. 조합 결과물은 직접 못 줍기 때문에 재료로 치환된다(재귀, 최대 4단계). 자세한 것은 3장.
3. **루트가 필요 없는 것 걸러내기** — 세 부류가 여기서 빠진다.
   - 이번 시즌에 없는 기프트 → 「획득 불가」
   - EXTREME 히든 전투 보상 → 「확률 보상」(층당 10%, 팩 선택으로 확정할 수 없다)
   - **범용 기프트** → 거의 모든 팩 풀에 있으므로 팩을 잡지 않는다. 「나올 수 있음」이지 확정이 아니다.
4. **지정 관측** — 사용자가 관측 슬롯에 넣은 기프트를 가장 먼저 처리한다. 이건 이 단계에서 유일한 사용자의 결정이라 시작 기프트보다도, 플래너의 추천보다도 앞선다. 관측한 기프트는 **확정**이 되어 범용 취급에서 빠진다.
5. **시작 기프트** — 시작 키워드 풀 3종 중 지금 필요한 것이 있으면 공짜로 하나 받는다. 가장 구하기 어려운 것을 고른다.
6. **팩 탐색 + 추천 관측** — 이 문서의 핵심. 4장에서 따로 설명한다. 남은 관측 슬롯은 ① 탐색이 포기한 기프트를 살리는 데, ② 기프트 하나 때문에 강제된 팩을 풀어 주는 데 쓴다.
7. **조합 일정** — 각 재료가 몇 층에서 손에 들어오는지 계산해 조합이 가능한 가장 이른 층을 정한다. 재료 하나라도 못 구하면 그 조합은 불가능으로 넘어가고, 「결과물만 목표」인 조합이라면 **남은 재료를 위한 방문도 취소**하고 탐색을 다시 돌린다.
8. **층 계획** — 층마다 팩·주울 기프트·관측 필요 여부·대체 가능한 팩·「이 팩은 4~5층 아무 데나 가능」 같은 창(window)을 붙인다.
9. **불가능한 조합** — 재료를 못 구한 조합을 이유와 함께 미해결로 남긴다.
10. **경고** — 조건 미충족, 범용 드랍, 늦은 조합, 상점 칸 초과, 탐색 상한 등.
11. **조립** — 「확보 M/T」와 「필요 팩 N」을 센다.

## 3. 조합은 재료로 펼쳐진다

조합 결과물은 상점에서 **재료를 모아 합성**해야 나온다. 그래서 계획은 결과물이 아니라 재료를 쫓는다.

- 게임은 대개 한 결과물에 레시피를 둘 준다. 짧은 것(중간 조합물을 쓰는 것)과 그걸 풀어쓴 긴 것. **상점 칸 수에 맞는 레시피가 이긴다.** 같으면 중첩이 적은 것, 그다음 더 흔한 재료를 쓰는 것을 고른다.
- **「반드시」는 재료까지 전염된다.** 결과물을 반드시로 두면 그 재료 전부가 반드시가 된다.
- 이미 손에 넣은 결과물(런 중 획득 표시)은 재료를 따라가지 않는다.

## 4. 팩 탐색

**층이 아니라 기프트를 기준으로 탐색한다.** 층을 기준으로 하면 「한 층에 들어갈 수 있는 팩」이 수십 개라 가짓수가 폭발한다. 기프트를 기준으로 하면 「이 기프트를 주는 (층, 팩) 칸」이 보통 열 개 미만이다.

지키는 규칙은 셋이다.

- 한 층에 팩 하나, 그리고 **한 런에서 같은 팩은 두 번 못 간다.**
- 층마다 그 층의 모드(Normal/Hard/평행중첩/EXTREME)에 나오는 팩만 들어갈 수 있다. Hard 전용 팩이 Normal 층에 나올 수 없는 것도 이 장치로 표현된다.
- 핀(이미 들어간 층)은 그대로 두고, 포기한 팩은 쓰지 않는다.

기프트마다 세 갈래를 시도한다. ① 이미 그 팩이 배정된 층 재사용 ② 빈 층에 새로 배정 ③ **이 기프트를 포기**. 셋째가 있는 이유는 전용 기프트 둘이 서로 배타적일 수 있기 때문이다.

### 무엇을 더 좋은 계획으로 보는가

순서대로 비교한다. 앞 항목에서 차이가 나면 뒤는 보지 않는다.

1. **반드시 기프트를 적게 버린 계획**
2. 보통 기프트를 적게 버린 계획
3. 강제되는 팩이 적은 계획 ← 화면의 「필요 팩」
4. 더 이른 층을 쓰는 계획

### 「근사 결과」의 의미

탐색은 노드 20만 개에서 멈춘다. 목표가 많으면 이 상한에 걸리고, 그때는 **그때까지 찾은 최선**을 보여 주면서 「근사 결과」 표시를 단다. 즉 **목표가 많을 때의 답은 최적이 아닐 수 있다.** 목표를 줄이면 정확해진다.

## 5. 「반드시」와 「보통」의 정확한 차이

앱에는 두 단계뿐이다(「포기」는 우선순위가 아니라 **선택 해제**다). 이 둘은 플래너에 닿기 전에 참/거짓 하나로 바뀐다.

반드시가 하는 일은 셋이다.

1. **비교의 최상위 항.** 반드시 기프트를 버리는 계획은, 보통 기프트를 아무리 많이 건지고 팩을 아무리 아껴도 이기지 못한다.
2. **관측 슬롯을 먼저 받는다.** 탐색이 버린 기프트를 관측으로 살릴 때 반드시가 앞선다.
3. **대안 루트에서 포기 후보가 되지 않는다.** 「무엇을 포기할까」를 제안할 때 반드시는 후보에서 빠진다.

반드시가 **하지 않는** 일도 분명히 해 둔다.

- 탐색이 후보를 방문하는 **순서는 바꾸지 않는다.** (2026-09-14 이전에는 바꿨고, 그것이 아래 사고의 원인이었다.)
- 층을 앞당기거나 팩을 더 잡아 주지 않는다.

### 실제로 있었던 일 — 반드시로 올렸더니 확보가 줄었다

제보: 목표 32개가 전부 보통일 때는 32/32였는데, 데스페라도 하나를 반드시로 올리자 30/32가 되었다.

원인은 **탐색의 방문 순서**였다. 예전 코드는 후보를 「필수 먼저 → 제약이 심한 것 먼저」로 정렬했다. 탐색이 상한에 걸리는 크기에서는 방문 순서가 곧 결과다. 전부 보통이거나 전부 반드시이면 정렬이 「제약이 심한 것 먼저」로 떨어져 완전한 답을 찾는데, **하나만 반드시**이면 그 후보 하나가 제약과 무관하게 맨 앞으로 끌려 나와 순서가 흐트러지고, 상한 안에서 더 나쁜 답에 멈췄다.

고친 방법: 정렬을 **「제약이 심한 것 먼저 → 같으면 필수 먼저」**로 되돌렸다. 우선순위는 위의 비교 규칙이 이미 지키고 있으므로 순서로 강제할 필요가 없다. 지금은 세 경우가 모두 같은 32/32 루트를 낸다.

**그래도 결과가 달라질 수 있는 경우**: 목표를 정말로 한 런에 다 담을 수 없을 때다. 그때는 무엇을 버릴지가 바뀌므로 층 배정도 달라진다. 이건 의도된 동작이다.

## 6. 관측 슬롯이 쓰이는 순서

E.G.O 기프트 관측은 런 시작 때 최대 3개를 확정으로 준다. 슬롯은 이 순서로 쓴다.

1. **사용자 지정** — 무조건 먼저. 관측할 수 없는 기프트, 한도를 넘은 것, 이번 계획의 목표가 아닌 것은 제외하고 그 사실을 경고로 알린다. 이미 손에 넣었거나 이미 포기한 기프트의 지정은 조용히 건너뛴다.
2. **구조** — 탐색이 포기한 기프트를 관측으로 살린다. 그 기프트를 직접 관측할 수 없으면, 그 층을 혼자 차지하던 다른 기프트를 대신 관측해 층을 비워 준다.
3. **유연성** — 오직 기프트 하나 때문에 강제된 팩을, 그 기프트를 관측으로 바꿔 풀어 준다. 방문해야 할 팩이 하나 줄어든다.

런 도중(2층 이후)에는 2·3을 하지 않는다. 관측은 런 시작에만 있기 때문이다.

**층 관측(테마팩 관측)은 이것과 다른 것이다.** 계획이 어떤 층에 특정 팩을 강제하는데 그 팩이 제시되지 않으면 별빛으로 관측해야 한다. 그 비용이 화면의 「별빛」이다.

## 7. 미해결과 경고 읽는 법

### 미해결 — 왜 이 기프트를 못 넣었나

| 표시 | 뜻 |
|---|---|
| 팩 충돌 | 다른 전용 기프트와 층이 겹쳐 한 런에 같이 넣을 수 없다 |
| 층 범위 밖 | 그 기프트를 주는 팩이 계획한 층(또는 남은 층)에 없다 |
| 포기한 팩 | 그 기프트를 주는 팩을 전부 포기했다 |
| 재료 미해결 | 조합 재료를 못 구했다 / 레시피가 없다 / 조합 단계가 너무 깊다 |
| 난이도 제한 | Hard 전용인데 Normal로 계획했다 |
| 확률 보상 | EXTREME 히든 전투로만 나온다. 루트로 확정할 수 없다 |
| 획득 불가 | 이번 시즌에 없는 기프트다 |
| 수집 실패 | 이번 런에서 실패로 표시했다 |

### 경고 — 계획은 됐지만 알아 둘 것

「범용 기프트는 확정이 아님」, 「조건을 충족하지 못하는 기프트 N개」, 「마지막 층에서야 재료가 모임」, 「재료가 상점 칸을 넘음」, 「탐색 한도(근사 결과)」, 「Hard로 올리면 루트가 넓어짐」, 「평행중첩 때문에 1층부터 Hard로 계획함」 등이 있다.

## 8. 숫자를 오해하지 않기

- **「필요 팩 N」은 계획이 강제하는 층의 수**다. 0이면 아무 팩이나 잡아도 목표가 채워진다는 뜻이지, 계획이 없다는 뜻이 아니다.
- **「확보 M/T」의 T는 고른 기프트 수**다. 조합 재료는 세지 않는다. 재료를 못 구해 결과물이 미해결이 되면 M이 줄어든다.
- **범용 기프트는 계획에 층이 잡히지 않는다.** 「나올 수 있음」이라 상점·새로고침과 함께 노려야 한다.
- **포함하기로 한 팩은 「보통」 기프트보다 강하다.** 팩을 포함으로 지정하면 그 팩을 넣기 위해 보통 기프트가 밀릴 수 있다.
- **같은 층을 두고 경쟁이 생기면 대안 루트가 뜬다.** 「무엇을 버리면 나머지가 들어가는가」를 계산해 보여 주는 것이고, 반드시로 둔 기프트는 후보에서 빠진다.

## 9. 알려진 한계

- **두 조합이 같은 재료를 각각 필요로 할 때, 계획은 그 재료의 층을 한 번만 확보한다.** 상점은 재료를 소모하므로 실제로는 두 번 주워야 한다. 지금은 아이템 화면이 이런 조합 둘을 **「얽힘」**으로 막아 두는 것으로 대응하고 있다.
- 탐색 상한이 고정값(20만 노드)이라 목표 수에 따라 자동으로 늘지 않는다.
- 조건(키워드·소속) 판정은 계획을 막지 않는다. 조건을 못 채워도 루트는 그대로 계산되고 경고만 붙는다.

## 10. 직접 재현해 보기

공유 링크만 있으면 화면과 똑같은 계산을 명령줄에서 돌릴 수 있다.

```bash
npm run route -- --share '#s=…'          # 공유 링크 그대로 (반드시/보통까지 재현)
npm run route -- --share '#s=…' --explain --trace
npm run route -- --deck 10101,… --want 9088,… --must 9088 --floors 1-15 --difficulty hard
```

`--trace`는 각 기프트가 어느 단계에서 어떻게 처리됐는지 보여 준다. 화면과 숫자가 다르면 그 자체가 버그이니 알려 주면 된다.
